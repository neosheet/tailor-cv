# 09 — Persona/CV Supabase Cutover + Inline Section Picker

Supersedes [plans/08](08-persona-cv-split.md) for the Persona/CV data layer: instead
of a mocks-only rename, this executes the deferred Supabase migration for real and
adds the create/edit feature the mocks-only version never got — a "+" on every
Persona card that opens a large popup showing the actual Inventory table for that
pool, letting you pick which entries populate that section. Depends on
[specs/06-persona-cv-split.md](../specs/06-persona-cv-split.md) and
[specs/03-cv-selection.md](../specs/03-cv-selection.md).

**Why now, why bigger than plan 08 scoped:** plan 08 deliberately kept Personas/CVs
mock-only, since nothing in the app read them from Supabase yet. Once a real
create/edit UI was requested, that stopped making sense — a picker that writes
nowhere real isn't a feature. Mid-planning the user confirmed: cut over for real, and
create the Supabase tables if they don't exist yet.

**Locked-in decisions:**
1. Hero splits into 3 separate cards (Name, Headline, Summary) — every card maps to
   exactly one Inventory pool, matching Contact/Location/Social already being separate.
2. This pass wires only what's needed for section-content create/edit. Persona-level
   Edit (rename/note)/Duplicate/Delete stay disabled placeholders — except the
   unavoidable minimal "name a new Persona" step needed to create the initial row.
3. Picker is whole-entry only for v1 — picking an entry includes all its bullets by
   default. Per-bullet curation is a documented follow-up.
4. `personas.favorite`/`personas.tags` get real columns in this migration — keeps the
   Favorite toggle and tag badges built earlier working for real instead of removing
   already-shipped UI.

Confirmed live via `list_tables` against project `artmbeeadepxggbvfkdr` before
starting: old schema still in place, `cvs` (2 rows), `cv_sections` (22), `cv_items`
(38), `cv_lines` (47), all real UUIDs from a prior seed run.

## Phase 1 — Supabase migration + backfill

One `apply_migration` (schema only): renames `cvs`/`cv_sections`/`cv_items`/
`cv_lines` → `personas`/`persona_sections`/`persona_items`/`persona_lines` (data
preserved — real rename, not drop/recreate), renames their `cv_id` columns to
`persona_id`, renames the guard trigger function
`cv_line_belongs_to_item()`→`persona_line_belongs_to_item()`, renames constraints/
indexes so the new `cvs` table's autogenerated names don't collide, adds
`favorite boolean not null default false` + `tags text[] not null default '{}'` to
`personas`, and creates the new `cvs` table (`id, user_id, persona_id fk→personas,
template_id text (loose ref), name, note, created_at, updated_at`) with RLS, a touch
trigger, and indexes on `(user_id)`/`(persona_id)`.

Deliberately **not** in this migration: a DB-level unique constraint for "at most one
selected item" per pick-one Basics kind (spec 03 open point 4) — enforced in the new
`setPersonaSectionItems` mutator instead, so the migration stays scoped to what spec
06 already designed. Persona tags also skip the `assert_tags_registered()` registry
trigger Inventory tags get — plain `text[]`, organisational only.

Then a separate `execute_sql` backfill inserting 2 `cvs` rows for the two existing
personas, joined by name (not hardcoded UUIDs) against a `values` list carrying
`template_id: 'classic'` + the names/notes from `src/mocks/data/cvs.ts`.

## Phase 2 — Regenerate `database.types.ts`

Via the Supabase MCP `generate_typescript_types` tool, overwrite
`src/lib/database.types.ts`. Every new lib function in Phase 3 depends on this.

## Phase 3 — Data layer

- **`src/lib/persona-store.tsx`** (new) — `PersonaStoreProvider`/`usePersonaStore()`,
  mirrors `src/lib/inventory-store.tsx` exactly. One combined store for
  `personas`/`persona_sections`/`persona_items`/`persona_lines`/`cvs` — they're
  consumed together everywhere that matters (Used in CVs, `resolveCv`,
  `buildResumeDocument`), same rationale `InventoryStore` already bundles 4 tables.
  `DbPersona` redefined here schema-accurately (`id, userId, name, note, tags,
  favorite, createdAt, updatedAt` — no `deletedAt`, soft delete isn't implemented).
  Nested inside `InventoryStoreProvider` in `src/App.tsx`.
- **`src/lib/persona.ts`** (new) — selectors (`allPersonas`, `findPersona`,
  `personasUsingItem`, `personaUsageCount`, `buildResumeDocument` — ported from
  `mocks/persona.ts`, now taking explicit `PersonaData`/`InventoryData` args instead
  of closing over module state) plus mutators `createPersona`,
  `togglePersonaFavorite`, and the core one:
  `setPersonaSectionItems(store, inventory, personaId, kind, itemIds,
  previousItemIds)` — full-replaces one section's item selection (upsert
  `persona_sections`/`persona_items`, delete removed items which cascades their
  lines, insert `persona_lines` for newly-added items using all of their current
  lines), throwing up front if a pick-one Basics kind gets more than one id.
- **`src/lib/cv.ts`** (new) — `allCvs`, `findCv`, `resolveCv` selectors only. No
  `createCv` — "New CV" stays disabled, unchanged.

## Phase 4 — Reusable picker infrastructure

- **`pool-columns.tsx`**: moves Basics' column configs (currently local to
  `pages/inventory/basics.tsx`) into `POOL_COLUMNS`, widening it from
  `Partial<Record<...>>` to a total `Record<ItemKind, PoolColumn[]>` — the picker
  needs columns for all 17 kinds, not just the 11 non-Basics pools.
- **`use-pool-data.ts`** (new): extracts the `useInventoryStore()` +
  `POOL_COLUMNS[kind]` + `itemsOfKind` lookup `pool-page.tsx` already did inline, so
  the real page and the new picker dialog share it instead of duplicating it.
- **`pool-table.tsx`**: `PoolColumn.cell` gains a 4th param (`persona: PersonaStore`)
  — `PoolTable` now calls both `useInventoryStore()` and `usePersonaStore()`. Adds
  `selectAllHidden?` for single-select mode.
- **`pool-panel.tsx`**: new optional `mode`/`selectionMode`/`selected`/
  `onSelectedChange` props (all defaulted, every existing call site untouched) — in
  `"pick"` mode, `BulkActions` never renders and selection can be externally
  controlled/single-select. Add/Edit/Delete stay wired exactly as today.
- **`columns.tsx`**: `USAGE_COLUMN` reads `personaUsageCount` from the new 4th `cell`
  param instead of importing from mocks.
- **`item-detail-dialog.tsx`**: `DetailBody` adds `usePersonaStore()`.
- **`pool-picker-dialog.tsx`** (new): `PoolPickerDialog({kind, open, onOpenChange,
  title, singleSelect, initialSelected, onConfirm})` — large `Dialog`
  (`sm:max-w-6xl max-h-[90vh]`, new size precedent, nothing in the app exceeded
  `sm:max-w-3xl` before this), `PoolPanel` in pick mode inside `DialogBody`, footer
  with selected count + Cancel/Confirm.

## Phase 5 — `persona-detail.tsx` + `personas.tsx` rewrite

`personas.tsx`: mock imports swapped for the new lib/store; "New Persona" goes from
disabled to a minimal name-entry `Dialog` (new `new-persona-dialog.tsx`, one required
field, not the full `ItemDialog` machinery) that creates the row and navigates to
`/personas/:id`.

`persona-detail.tsx`: Hero splits into 3 cards (Name/Headline/Summary); all 17 cards
(6 Basics + 11 pools) always render now, populated or empty-state, each with a
"+"/manage button; one shared `PoolPickerDialog` instance per page, controlled by
`openKind: ItemKind | null`; a local `itemIdsForKind` helper cross-references
`personaItems` against `InventoryStore` (since `persona_items` carries no `kind`
column) to seed `initialSelected` and compute `previousItemIds` on confirm.

## Phase 6 — Mechanical mock→lib swaps

`cv-list-panel.tsx`, `templates-panel.tsx`, `cv-print.tsx`, `add-to-persona-dialog.tsx`,
and 5 files under `components/cv/` — same pattern: swap mock imports for
`@/lib/persona`/`@/lib/cv`, read both stores, pass explicit data into the
now-multi-arg selectors.

## Phase 7 — `scripts/seed.ts`

Table/column renames matching Phase 1, plus a new `cvs` insert block using a
`personaIdMap` (mock slug → generated UUID) mirroring the file's existing
`itemIdMap`/`lineIdMap` pattern. **Not re-run** against the live project — already
seeded, script is non-idempotent; this phase is code-correctness only.

## Phase 8 — Cleanup

Delete `src/mocks/persona.ts` and `src/mocks/cv.ts` (confirmed dead — `seed.ts` never
imported them, only `mocks/data/*`/`mocks/types.ts`). Keep `mocks/data/personas.ts`,
`mocks/data/cvs.ts`, and the `Source*` types (seed.ts still needs them). Remove the
now-fully-dead `DbPersona` export from `mocks/types.ts`; keep `DbPersonaSection`/
`DbPersonaItem`/`DbPersonaLine`/`DbCv` there since `lib/persona.ts` re-exports those
(already schema-accurate).

## Verification

Per-phase typecheck/build gates throughout. Two live-browser checkpoints where real
Supabase writes first happen: Phase 4 (regression check on unmodified
`/inventory/work` and `/inventory/basics` after the shared-infra changes) and Phase 5
(the actual create → pick → confirm flow, cross-checked against the live DB via
`execute_sql`, including one pick-one Basics kind to confirm replace-not-add
semantics). Final pass: full typecheck/lint/build, then a walkthrough of
`/personas` → create → populate several sections → `/cvs` → `/cvs/:id/print` → back to
an Inventory item's detail dialog to confirm "Used in Personas" reflects it.

## Open items carried forward

- Per-bullet/line curation inside the picker — deferred, whole-entry only for now.
- Persona-level Edit (rename/note)/Duplicate/Delete — stay disabled placeholders.
- DB-level enforcement of "at most one" for pick-one Basics kinds — app-layer only
  for now (spec 03 open point 4, still open).
- `cvs.template_id` stays a loose string reference, not a real FK (unchanged from
  plan 08 — no `cv_templates` table exists yet).
- Applications binding — still unspecced, unaffected by this plan.
